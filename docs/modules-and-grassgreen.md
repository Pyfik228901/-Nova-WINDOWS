# Модули и интеграция с языком GrassGreen (FFI)

В данном документе описывается система импорта модулей в языке **N&S**, а также архитектура моста внешних вызовов (Foreign Function Interface, FFI) с компилятором системного языка **GrassGreen**.

---

## 1. Система импорта модулей

Инструкция `import` используется для подключения стандартных модулей, сторонних библиотек и локальных скриптов N&S.

### 1.1. Синтаксис инструкции `import`
```javascript
import "<путь_или_имя_модуля>" [as <псевдоним>];
```
* Если псевдоним `as` опущен, модуль регистрируется в текущей области видимости под именем файла (без расширения) или под стандартным системным именем.
* Рекомендуется всегда указывать явный псевдоним `as` для чистоты кода.

### 1.2. Импорт стандартных библиотек
Язык N&S включает следующие встроенные модули:
* `"io"` — базовый ввод-вывод и работа с файловой системой.
* `"math"` — математические вычисления и генератор случайных чисел.
* `"cli"` — работа с аргументами командной строки и ANSI-стилизация терминала.
* `"web"` — встроенный HTTP-сервер, маршрутизация и JSON.
* `"game2d"` — 2D-графика на базе HTML5 Canvas в браузере.

Пример:
```javascript
import "io" as io
import "math" as math

print(math.sqrt(64)); // 8
```

### 1.3. Импорт локальных файлов `.ns` и `.nova`
Вы можете разделять код проекта на несколько файлов и импортировать их по относительному или абсолютному пути:
```javascript
// helpers.ns
func calculate_discount(price, percent) {
    return price * (1.0 - percent / 100.0);
}

// main.ns
import "./helpers.ns" as helpers

let final_price = helpers.calculate_discount(1000, 15);
print("Цена со скидкой: " + final_price); // 850
```
* **Разрешение путей:** Относительные пути вычисляются относительно директории выполняемого скрипта. Если скрипт запущен через REPL или `eval`, поиск выполняется относительно текущей рабочей директории.
* При импорте исполняется весь код подключаемого файла, а экспортируемые переменные и функции собираются в ассоциативную карту `Map` и возвращаются в модуль.

## 2. Интеграция с языком GrassGreen (FFI)

**GrassGreen** — это системный язык программирования (разработанный [m1oky](https://github.com/m1oky/GrassGreen)), ориентированный на низкоуровневую разработку и создание ядер операционных систем.

Язык N&S предоставляет нативный мост FFI, позволяющий бесшовно связывать легковесные скрипты N&S с производительным нативным кодом GrassGreen.

### 2.1. Поиск и обнаружение компилятора GrassGreen
При запуске кода с директивами GrassGreen интерпретатор N&S автоматически выполняет поиск бинарного файла компилятора (`grg.exe` или `grassc.exe` на Windows, `grg` / `grassc` на Unix-системах) в следующем порядке:
1. Переменная окружения `GRASSGREEN_HOME`: проверяются подпапки `bin/grg.exe`, `bin/grassc.exe` и корень `$GRASSGREEN_HOME/grg.exe`.
2. Стандартный системный каталог Windows: `C:\GrassGreen\bin\grg.exe` или `C:\GrassGreen\bin\grassc.exe`.
3. Системная переменная `PATH`.

Если компилятор не найден, рантайм выводит понятное предупреждение:
```text
[GrassGreen FFI] [Warning] Компилятор GrassGreen (grg / grassc) не найден в системе.
Для выполнения блоков extern "grass" и файлов .grass установите GrassGreen:
  Документация и загрузка: https://grassgreen.info
  Исходный код: https://github.com/m1oky/GrassGreen
```
При этом интерпретатор N&S **не падает с ошибкой**, а возвращает объект-заглушку `{"available": false}`, что позволяет скрипту мягко обработать отсутствие компилятора.

### 2.2. Импорт файлов `.grass`
Вы можете напрямую импортировать файл `.grass` в скрипт N&S:

```javascript
import "./backend_logic.grass" as gg
```
или с явным указанием типа:
```javascript
import grass "./backend_logic.grass" as gg
```

#### Объект импортированного модуля:
Импортированный модуль представляет собой объект `Map`, содержащий:
* `path` (`String`) — абсолютный или относительный путь к файлу.
* `available` (`Bool`) — флаг доступности компилятора и файла.
* `run(args...)` (`NativeFunction`) — метод запуска исходного файла целиком.

#### Запуск модуля целиком (`run`):
- **Сигнатура:** `gg.run(args...: Any) -> Any`
- **Описание:** Выполняет весь файл `.grass` через запуск `grg -r <file.grass>` и возвращает результат его выполнения. Если вывод GrassGreen представляет собой валидный JSON, рантайм автоматически преобразует его в структуру N&S (`Map` или `Array`). Если вывод является числом, возвращается `Int` или `Float`. В противном случае возвращается `String`.
- **Пример:**
  ```javascript
  import "./main.grass" as gg
  let output = gg.run();
  ```

#### Вызов именованных функций из `.grass` с аргументами:
N&S поддерживает динамический вызов функций, объявленных внутри `.grass`-файла:
- **Сигнатура:** `gg.имя_функции(arg1: Any, arg2: Any, ...) -> Any`
- **Описание:** При обращении к любому свойству объекта `gg`, не являющемуся служебным, N&S генерирует оптимизированную обёртку на GrassGreen с директивой `#include`, передаёт аргументы в функцию, компилирует её вызовом `grg -r` и парсит возвращённое значение.
- **Пример:**
  Пусть в `main.grass` объявлена функция:
  ```cpp
  !GrassGreen!
  
  int calculate_power(int base, int exp) {
      int res = 1;
      for (int i = 0; i < exp; i = i + 1) {
          res = res * base;
      }
      return res;
  }
  
  int main() {
      return 0;
  }
  ```
  В коде N&S вызов выполняется так:
  ```javascript
  import "./main.grass" as gg

  let result = gg.calculate_power(2, 8);
  print(result); // 256
  ```

### 2.3. Встроенный блок `extern "grass"`

Для небольших нативных фрагментов или высокопроизводительных системных вычислений вы можете встраивать код GrassGreen прямо в тело скрипта N&S с помощью блока `extern "grass" { ... }`.

- **Сигнатура конструкции:** `extern "grass" { <исходный_код_на_grassgreen> }`
- **Описание:**
  * Код внутри фигурных скобок считывается парсером с сохранением точных исходных байтов (включая операторы потока `<<`, `>>`).
  * Если код не содержит заголовка `!GrassGreen!` или точки входа `main()`, рантайм автоматически оборачивает его в валидную функцию `int main() { ... return 0; }`.
  * Создаётся изолированный временный файл в каталоге ОС, компилируется компилятором `grg -r` и немедленно удаляется после завершения.
  * Вывод фильтруется от служебных сообщений виртуальной машины (`[GrassVM]:`) и возвращается в N&S.

- **Пример использования:**
  ```javascript
  print("[Info] Вызов нативного кода GrassGreen:");

  extern "grass" {
      int a = 20;
      int b = 22;
      gout << "[GrassGreen Inline] Computed sum: " << (a + b) << endl;
  }
  ```

- **Результат в терминале:**
  ```text
  [Info] Вызов нативного кода GrassGreen:
  [GrassGreen Inline] Computed sum: 42
  ```

### 2.4. Преобразование типов между GrassGreen и N&S

Мост FFI поддерживает двустороннюю маршализацию типов через stdout/JSON:
* Целые числа C-ABI (`int`, `i64`) преобразуются в `Value::Int`.
* Вещественные числа (`float`, `double`) преобразуются в `Value::Float`.
* Строки преобразуются в `Value::String`.
* Сериализованные объекты JSON (`{"key": "value"}`) превращаются в нативные ассоциативные массивы `Value::Map` N&S.
* Списки JSON (`[1, 2, 3]`) преобразуются в `Value::Array`.
